# Browser release completion brief

Goal: deliver a complete, playable school-laptop browser release candidate, not an asset demo. Reuse AGENTS.md, README, roadmap, existing asset/reference records and test evidence. Pin editable source, served build and backend revisions before changes. Never substitute an older export to make verification pass.

Run implementation, performance and independent playtest lanes with separate ownership and worktrees. The lead integrates the results. Let offline work continue when a browser slot is busy; serialize graphics measurements. Reproduce one concrete player-facing gap, implement the smallest effective change, replay the same action on the exact candidate, and retain only verified improvements.

Verify ordinary teacher/host and player journeys with clean browser contexts: join, play the objective through round end, reconnect, start a clean rematch, and verify no stale state. For solo and multiplayer, record the device and resolution, compare cold/warm runs, and report p95/p99 frame intervals and hitches over 50 ms per minute. A pass on a development PC does not clear school hardware. Compare art at ordinary gameplay camera angles; reject polish that makes route choices harder to read.

Update the existing issue and project docs with exact candidate revision, verified outcomes, remaining blockers and reproducible test steps. Stop when one coherent launchable candidate meets the agreed gates, or record the blocker and continue independent work. Do not weaken gates, create a new deployment, or include credentials, student data, traces or licensed source assets in the public repository.
